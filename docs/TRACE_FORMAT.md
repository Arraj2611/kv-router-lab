# Trace format

`python sim/cache_router_sim.py --trace FILE` (or **Load trace…** on the page) replays a request trace instead of the synthetic workload. One JSON object per line (JSONL); blank lines are ignored.

| field | type | required | meaning |
|---|---|---|---|
| `t` | number >= 0 | yes | arrival time in seconds. Any origin; the first request becomes t = 0 |
| `session` | string or integer | yes | requests with the same value are one chat; each turn's history is cached per session |
| `tokens` | integer >= 1 | yes | full prompt length of this request |
| `prefix_id` | string or integer | yes | requests with the same id share a prompt prefix (e.g. one system prompt) |
| `prefix_tokens` | integer >= 0 | no | length of that shared prefix; clamped to `tokens` |

Example line: `{"t":0.34,"session":"s000","tokens":1305,"prefix_id":"assistant-a","prefix_tokens":1213}`

Notes:
- Without `prefix_tokens`, the simulator assumes every request with that `prefix_id` shares the length of the **shortest** prompt seen for it. That is a guess and can overstate sharing; a warning names the affected ids.
- Blocks are 16 tokens; only whole blocks are cached, so `prefix_tokens` is rounded down.
- Unsorted input is sorted by `t` (ties keep file order). Bad input is rejected with `line N: ...`.
- With a trace, `--rates`, `--duration` and the workload flags are ignored; the rate is derived from the trace.
- Decoding, output length and think time are not modelled; only arrival time and prompt shape matter.

`docs/example_trace.jsonl` is **synthetic** (3 prefixes, 399 requests, generated by `tools/make_example_trace.py`). It is not real traffic; it exists to document the format and to drive the parity check. `tools/trace_check.py` checks that the Python and JS parsers accept and reject the same inputs.
